# Deploying to Render

`render.yaml` describes the hosted stack. It mirrors `compose.yaml` without Metabase:

| Render resource | Role | Reachable from |
|---|---|---|
| `crane-ifs-web` (web, Docker) | nginx: the built front end; `/api/` proxied to the API | the internet (Render TLS) |
| `crane-ifs-api` (private service) | FastAPI; `python -m app.migrate` runs before each deploy | the web service and worker only |
| `crane-ifs-worker` (background worker) | nightly sync at 02:30 America/Chicago | nothing inbound |
| `crane-ifs-db` (PostgreSQL 16) | the `facilities` database | the three services; `ipAllowList: []` |

All three services deploy `main` on every push, so `render.yaml` must be on `main` before the
blueprint is applied. Plans: three `0.5c-512mb` instances and a `0.5c-1g` database.

## 1. Apply the blueprint

Render dashboard > New > Blueprint > the `tussiri/PnLDashboard` repository, branch `main`.
Render asks for every `sync: false` value, all on `crane-ifs-api`; the worker reads the WinTeam,
Sarus and Relay values from the API service, so each is entered once:

| Variable | Value |
|---|---|
| `APP_USERS_JSON` | Leave empty. Users are created in Admin > Users; it only adds optional environment users (docs/auth-rbac.md). |
| `WINTEAM_BASE_URL`, `WINTEAM_TENANT_ID`, `WINTEAM_SUBSCRIPTION_KEY`, `WINTEAM_CUSTOMER_NUMBERS` | Same as the local `.env`. `WINTEAM_ENABLED` is `true`, so the API will not start without the first two. |
| `WINTEAM_SARUS_*` | Same as the local `.env`. |
| `RELAY_BASE_URL`, `RELAY_EXPORT_TOKEN` | Leave empty until Relay's dashboard export is deployed, then `https://relay.smcraneifs.app` and a token from Relay's `DASHBOARD_EXPORT_TOKENS`. |
| `COMPANYCAM_API_TOKEN` | Empty until there is a CompanyCam token. |
| `GRAPH_TENANT_ID`, `GRAPH_CLIENT_ID`, `GRAPH_CLIENT_SECRET` | The records mailbox app registration (docs/mail-inbox.md). Leave empty until it exists; `GRAPH_MAILBOX` is already records@smcraneifs.com. |

`APP_SESSION_SECRET`, `APP_SETUP_TOKEN` and `INGESTION_ADMIN_TOKEN` are generated by Render.

**First administrator:** do the data restore in step 2 first (the restore replaces the database), then open the site; the sign-in page shows **Create administrator** while no user
exists. Enter the setup code (Render > `crane-ifs-api` > Environment > `APP_SETUP_TOKEN`), a username
and a password. Add everyone else in Admin > Users.

The first deploy migrates an empty database. The dashboard then shows demo data (the marts are
empty) until step 2.

## 2. Restore the local data (one time)

WinTeam's API has no job-cost revenue; the revenue history lives in the local database (loaded
from the Finance_Dashboard export and uploads). Restore a dump of it over the empty schema.

1. Render > `crane-ifs-db` > Networking: add your current IP to the access list.
2. With the local stack running, run the script and paste the database's **External Database URL**
   (Render > `crane-ifs-db` > Connect) when it asks. Input is hidden and never stored. It dumps the
   local database fresh, replaces the Render database's contents with it (`--clean` drops the empty
   schema the first deploy created; the migration history matches the repository), and prints row
   counts to confirm.

   ```bash
   ./scripts/restore-to-render.sh
   ```

3. Remove your IP from the access list again.
4. Reload the site. The restore replaces users too, so the sign-in page shows **Create administrator**
   again: use the setup code from step 1.

## 3. After go-live

* Nightly: the worker syncs WinTeam, Sarus and Relay (when configured), then rebuilds the marts.
* Report exports: emailed to records@smcraneifs.com and picked up by the mailbox poller
  (docs/mail-inbox.md), or uploaded in Admin > Imports. The import inbox folder is local only.
* Account settings made locally (featured accounts, job mapping) travel with the dump only; after
  the restore, change them in the hosted Admin.
